# Windows パッケージのビルド

**[English version →](building.md)**

Python がインストールされていない Windows PC でも動作するワンフォルダー構成の
`dist\zairyu-reader\zairyu-reader.exe` を生成します。

## 前提条件

- **Windows** の開発環境。クロスビルドはできません。
- Python 3.11 以降（64ビット）。
- 依存ライブラリのインストールとOCRモデルの配置が済んでいること
  （[installation.ja.md](installation.ja.md) を参照）。
- `pip install` とモデルのダウンロードのためのインターネット接続。以降は不要です。

## ビルド

```powershell
powershell -ExecutionPolicy Bypass -File scripts\build_windows.ps1
```

オプション:

```powershell
scripts\build_windows.ps1 -SkipTests          # テストを省略
scripts\build_windows.ps1 -Python "C:\Path\To\python.exe"
```

`-SkipTests` はパッケージングの問題を調べるためのものです。リリース用ビルドでは使用しないで
ください。

## ビルド時に検証される内容

次のいずれかが失敗した場合、パッケージは生成されません（この順に検証されます）。

1. **依存ライブラリ**（PyInstaller を含む）のインストール。
2. **配置済みOCRモデル**が `tools\verify_ocr_assets.py` に合格すること。マニフェストの全ハッシュ、
   メタデータと辞書の並び順、固定の BGR `[1, 3, 48, W]` 入力、CTC 出力クラス対応を検証します。
3. **ヘルス契約**が引き続き `app == "zairyu-reader"` を返すこと。ランチャーはこれを使って、
   同じポートを使う無関係なサービスと自分自身のサーバーを区別します。壊れるとプロセス識別が
   できなくなります。
4. **テストスイート**の成功（`-SkipTests` 指定時を除く）。
5. **`static\local.js` の構文**（Node.js がある場合）。無い場合はメッセージを出して省略します。
6. **アイコン**の再生成。
7. **必要な実行時リソース**がバンドルに含まれていること。静的ページ、OCRの4ファイル、
   トラストアンカーのマニフェスト、webview のサポートディレクトリ。
8. **スクリプトファイルが同梱されていないこと。** `dist\` 内のどこかに `.ps1`、`.bat`、`.cmd`
   があればビルドは失敗します。

8番目はパッケージングの確認ではなく、セキュリティ上の再発防止です。以前のバージョンには、
カード画像を `%TEMP%` に書き出して `powershell.exe -ExecutionPolicy Bypass` を実行する
PowerShell 製OCRヘルパーが同梱されていました。この経路は削除済みであり、この検査によって、
復活した場合は無言で出荷されるのではなくビルドが失敗します。

## パッケージに含まれるもの

- リーダー処理、プロトコルモジュール、署名検証。
- 担当者向けの静的ページ。
- ONNX Runtime CPU のネイティブライブラリと、検証済みの PP-OCRv6 モデル・メタデータ・辞書。
- 法務省のトラストアンカー。
- pywebview。

含まれないもの: Chromium や WebView2 のランタイム、外部インタープリター向けのスクリプト、
`tools\` の開発用ツール、テスト、ドキュメント、仕様書PDF。

## ワンファイルではなくワンフォルダーを採用している理由

ワンファイル構成の PyInstaller ビルドは、起動のたびにバンドル全体を `%TEMP%` に再展開します。
76 MB のモデルを含むと動作が遅く、ウイルス対策ソフトが毎回展開後のファイルを再検査します。
ワンフォルダー構成はこの両方を回避します。

## 配布方法

`dist\zairyu-reader` フォルダーごとコピーしてください。`zairyu-reader.exe` は、隣にある
`_internal` フォルダーが無いと動作しません。

実行ファイルには署名がありません。初めて実行する PC では Windows SmartScreen の警告が
表示されます。コード署名を行うかどうかは開発者の判断であり、このビルドには含まれていません。

## Windows Server 2016

次が必要です。

- デスクトップ エクスペリエンス — **Server Core ではこのUIを表示できません**;
- アプリシェル用にインストール済みの Chromium 系ブラウザー;
- PC/SC 対応のリーダードライバーと Windows の Smart Card サービス;
- 配置済み ONNX Runtime とモデルの互換性チェックに合格すること。

この環境では WebView2 は必須のシェルではなく、強制指定できる任意のモードです。

## ビルドで確認できないこと

Python のテストは合成データで動作します。**次の点は確認できません。** Windows Server 2016
での互換性、Chromium アプリモードの挙動、対象ハードウェアでの ONNX Runtime とモデルの互換性、
WebView2 の挙動、リーダードライバーの互換性。

これらは、許可されたハードウェアを用いて対象環境で手動確認してください。
[リリースチェックリスト](../RELEASE_CHECKLIST.ja.md)のハードウェア確認項目をご覧ください。

## ランチャーの制約

ランチャーは、自分が起動した Chromium プロセスのみを監視し、無関係な Chrome や Edge の
プロセスを終了させることはありません。Chromium は、同じプロファイルを使う既存プロセスに
新しいアプリウィンドウを委譲することがあり、その場合、起動用プロセスは直ちに終了します。
このときランチャーは、即座にサーバーを止めるのではなく、短い猶予時間だけサーバーを維持します。
委譲されたウィンドウがその後いつ閉じられたかを確実に検出することはできません。

サーバーを確実に自動終了させたい場合は、再起動の前に既存のアプリウィンドウを閉じてください。

- [ ] `-SkipTests` を**付けずに**フルビルドを実行する。
- [ ] 表示された配布サイズが想定どおりであることを確認する（およそ 150〜200 MB）。
- [ ] Python の入っていないクリーンな Windows PC で `.exe` を起動する。
- [ ] 許可されたカードを1枚、最初から最後まで読み取り、17項目と署名状態を確認する。
- [ ] コピー結果が貼り付け先のシステムに正しく入ることを確認する。
- [ ] 使用したリーダーの型番、Windows のバージョン、確認したカード世代を記録する。
